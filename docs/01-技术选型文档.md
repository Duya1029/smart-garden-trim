# 智慧园林·树木智能修剪决策平台 — 技术选型文档

> 版本：v1.0　　编制日期：2026-10-18

---

## 一、项目概述

### 1.1 项目背景

城市园林与果园的树木修剪长期依赖人工经验：修剪时机靠"看"，修剪方案靠"猜"，修剪过程无留痕，修剪效果无评价。本项目构建一套 **"任务派发 → 现场拍照 → AI 识别 → 方案可视 → 现场实施 → 记录归档 → 客户评价 → 数据看板"** 的闭环平台，把园林修剪从"经验驱动"升级为"数据 + AI 驱动"。

### 1.2 建设目标

| 目标 | 说明 |
| --- | --- |
| 档案数字化 | 树木"一树一码"，记录树种、位置、树龄、栽种时间、所属客户 |
| 任务流程化 | 客户发起需求 → 管理员审核派单 → 养护人员接单执行 → 提交记录 |
| 决策智能化 | 现场照片经 AI 识别，红线标出建议剪除旁枝、绿线标出保留枝条，并给出文字建议 |
| 评价可视化 | 客户对每次修剪评分并写评语，形成历史趋势曲线 |
| 管理数据化 | 修剪棵数、区域分布、任务完成率等指标看板化 |

### 1.3 角色与核心诉求

| 角色 | 代码 | 核心诉求 |
| --- | --- | --- |
| 管理员 | `ADMIN` | 账号/组织架构管理、树木档案管理、全量记录与图片查看、数据统计看板 |
| 养护人员（园林工人/果农） | `WORKER` | 接单、上传现场照片、调用 AI 获取修剪方案、填写实际修剪情况并提交 |
| 客户（物业/果园负责人） | `CLIENT` | 查看名下树木与生长档案、发起修剪需求、查看报告与评语、查看评分趋势 |

## 三、前端选型说明

### 3.1 为什么是 Vue3 + Vite

- **Vue3 组合式 API**：`<script setup>` 让"一个页面的数据 + 方法 + 生命周期"聚合在一处，页面组件可读性显著优于选项式 API。
- **Vite**：开发态基于原生 ESM，无需打包即可热更新；生产态 Rollup 打包，产物体积可控。
- **VSCode 搭建**：项目根目录提供 `.vscode/extensions.json` 与 `jsconfig.json`，推荐安装 `Vue - Official`、`ESLint`、`Prettier` 三个扩展即可获得完整语法提示与格式化。

### 3.2 前端分层

```
src/
├── api/          对接后端 REST 接口，一个业务模块一个文件
├── assets/       静态资源（样式、图标）
├── components/   通用组件（图片上传、AI 标注画布、分页表格等）
├── layout/       主框架布局（侧边菜单 + 顶栏 + 面包屑 + 标签页）
├── router/       路由表 + 权限守卫 + 动态菜单生成
├── store/        Pinia：user（登录态/权限）、app（菜单折叠）、dict（字典缓存）
├── utils/        request.js（Axios 封装）、auth.js（token 存取）、date.js
├── views/        业务页面，按角色分子目录 admin / worker / client
├── App.vue
└── main.js
```

### 3.3 关键约定

| 约定 | 说明 |
| --- | --- |
| 请求基地址 | `VITE_API_BASE`，开发态 `/api`（Vite proxy 到 8080），生产态由 Nginx 反向代理 |
| Token 注入 | Axios 请求拦截器统一加 `Authorization: Bearer <token>` |
| 响应解包 | 后端统一返回 `{code,msg,data}`，响应拦截器只把 `data` 交给业务代码 |
| 401 处理 | 响应拦截器捕获 401/`code=401` → 清空 Pinia + `router.push('/login')` |
| 权限控制 | 路由 `meta.roles` 声明可访问角色，全局前置守卫校验；菜单由路由表过滤生成 |
| AI 标注渲染 | 使用 SVG 覆盖层绘制线段（`<line>`），坐标使用 **归一化 0~1** 的 x1/y1/x2/y2，适配任意分辨率图片 |

## 四、后端选型说明

### 4.1 为什么是 Spring Boot 3 + Spring MVC + MyBatis

- **Spring Boot 3.2 + JDK 17**：满足企业环境对 LTS 的要求；内嵌 Tomcat 免去单独部署 Web 容器。
- **Spring MVC**：注解式开发，`@RestController` 直接返回 JSON；配合 `@RestControllerAdvice` 做全局异常兜底。
- **MyBatis（XML 配置 SQL）**：本项目所有 SQL 均维护在 `src/main/resources/mapper/*.xml`，Java Mapper 接口只声明方法签名。这样做的收益是——SQL 可以单独交给 DBA Review、可用数据库客户端直接复制执行、动态 SQL（`<if>` / `<foreach>`）比注解方式更易读。

### 4.2 包结构（按规范分包）

```

├── SmartGardenApplication.java        启动类
├── common/                            通用返回与异常

│   ├── PageResult.java                分页响应体 {total,list}

│   └── exception/

├── config/                            配置类
```

### 4.3 AI 识别模块设计（Mock 优先，预留真实接入）

需求明确"AI 识别部分可先提供模拟返回数据（Mock），并预留真实模型接入的接口"，因此按**策略模式 + 配置开关**设计：

```
controller  AiController
                │
                ▼
service     BranchAnalysisService  ──根据 ai.provider 选择实现──┐
                │                                              │
                ├── MockBranchAnalysisServiceImpl   (ai.provider=mock) 返回模拟数据
                └── HttpBranchAnalysisServiceImpl   (ai.provider=http) 调用真实模型 HTTP 接口
                                                                       │
                                                        ai.endpoint / ai.api-key / ai.timeout
```

- 真实模型只需实现 `BranchAnalysisService` 接口或提供一个兼容的 HTTP 端点，无需改动上层业务代码。
- Mock 实现按"树种 + 树形轮廓"生成若干条归一化坐标线段，红线（剪除）与绿线（保留）各若干条，并返回一段中文修剪建议文本，`isMock = true`。
- 数据库中 `ai_analysis.is_mock` 字段保留首次分析是否来自 Mock，便于上线后区分数据来源。

## 五、数据库选型

| 项 | 取值 |
| --- | --- |
| 数据库 | Microsoft SQL Server 2019 / 2022 |
| 客户端 | SQL Server Management Studio 22 (SSMS 22) |
| 数据库名 | `smart_garden` |
| 字符集 | `Chinese_PRC_CI_AS`（默认排序规则，`nvarchar` 存中文） |
| 驱动 | `com.microsoft.sqlserver:mssql-jdbc:12.6.1.jre11` |
| 连接 URL | `jdbc:sqlserver://localhost:1433;databaseName=smart_garden;encrypt=false;trustServerCertificate=true` |

### 5.1 表清单（8 张）

| 表名 | 中文名 | 说明 |
| --- | --- | --- |
| `sys_dept` | 组织架构表 | 部门 / 养护队，树形结构（`parent_id`） |
| `sys_user` | 账号表 | 三种角色，客户账号关联 `sys_client` |
| `sys_client` | 客户主体表 | 物业 / 果园等客户实体 |
| `tree` | 树木档案表 | 树种、位置、树龄、栽种时间、所属客户、归属养护队 |
| `trim_request` | 修剪需求表 | 客户发起，含预约时间、地点、备注、审核状态 |
| `trim_task` | 修剪任务表 | 需求审核后派单，或管理员直接派单 |
| `trim_record` | 修剪记录表 | 实际修剪情况、AI 建议、客户评分与评语 |
| `trim_record_image` | 记录图片表 | 现场照片：SCENE / BEFORE / AFTER / AI_MARKED |
| `ai_analysis` | AI 分析结果表 | 剪除/保留枝条坐标 JSON、建议文本、置信度、是否 Mock |

### 5.2 关键设计说明

- **主键**：统一 `BIGINT IDENTITY(1,1)`，Java 侧用 `Long`。
- **逻辑外键**：表间不做物理外键约束，改为在 Service 层校验，避免多表删除时的锁竞争。
- **时间字段**：统一 `datetime2(0)`，Java 侧 `LocalDateTime`，MyBatis 开启驼峰映射。
- **软删除**：本次未引入 `deleted` 字段，删除为物理删除；如后续需要可统一增加。
- **坐标存储**：`ai_analysis.cut_branches` / `keep_branches` 使用 `nvarchar(max)` 存 JSON 数组，由 Jackson 序列化，避免为坐标单独建表。

## 六、部署架构

```
                    ┌───────────────────────────────┐
  浏览器  ────────► │  Nginx  (80)                  │
                    │  ├─ /            → 前端静态资源 │
                    │  └─ /api/        → 反向代理    │
                    └───────────┬───────────────────┘
                                │ http://127.0.0.1:8080
                                ▼
                    ┌───────────────────────────────┐
                    │  Spring Boot (内嵌 Tomcat)     │
                    │  context-path = /api           │
                    │  port = 8080                   │
                    └───────────┬───────────────────┘
                                │ mssql-jdbc
                                ▼
                    ┌───────────────────────────────┐
                    │  SQL Server  :1433            │
                    │  database = smart_garden       │
                    └───────────────────────────────┘
                                ▲
                                │ HTTP（可选项）
                    ┌───────────┴───────────────────┐
                    │  真实 AI 模型服务（预留）        │
                    └───────────────────────────────┘
```

- **前端**：`npm run build` 产出 `dist/`，由 Nginx 托管，开启 gzip 与静态缓存。
- **后端**：`java -jar smart-garden-trim.jar`，内嵌 Tomcat 监听 8080，`server.servlet.context-path: /api`。
- **跨域**：生产环境同源（Nginx 统一入口）无需跨域；开发环境放开 5173 端口。
