# 智慧园林·树木智能修剪决策平台 — 接口文档

> 版本：v1.0　　服务地址（开发）：`http://localhost:8080/api`　　生产：`http://<域名>/api`

---

## 一、通用约定

### 1.1 请求头

| 名称 | 是否必须 | 说明 |
| --- | --- | --- |
| `Content-Type` | 是 | `application/json;charset=UTF-8`（文件上传为 `multipart/form-data`） |
| `Authorization` | 登录后必须 | `Bearer <token>` |

### 1.2 统一响应体

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 200 成功；401 未登录/令牌失效；403 无权限；500 业务或系统异常 |
| `msg` | string | 提示信息 |
| `data` | any | 业务数据，可为对象、数组、分页对象或 null |

### 1.3 分页响应体

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 128,
    "list": []
  }
}
```

分页请求统一参数：`pageNum`（从 1 开始，默认 1）、`pageSize`（默认 10）。

### 1.4 状态码表

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 200 | 成功 | 正常渲染 |
| 401 | 未登录 / Token 过期 | 清空登录态，跳转登录页 |
| 403 | 已登录但无权限 | 提示"无权限访问" |
| 500 | 业务异常 / 系统异常 | 弹出 `msg` |

### 1.5 枚举字典

**角色 role**

| 值 | 含义 |
| --- | --- |
| `ADMIN` | 管理员 |
| `WORKER` | 养护人员 |
| `CLIENT` | 客户 |

**需求状态 trim_request.status**

| 值 | 含义 |
| --- | --- |
| `PENDING` | 待审核 |
| `AUDITED` | 已审核待派单 |
| `DISPATCHED` | 已派单 |
| `COMPLETED` | 已完成 |
| `REJECTED` | 已驳回 |
| `CANCELLED` | 已取消 |

**任务状态 trim_task.status**

| 值 | 含义 |
| --- | --- |
| `PENDING` | 待接单 |
| `ACCEPTED` | 已接单 |
| `PROCESSING` | 修剪中 |
| `SUBMITTED` | 已提交记录 |
| `DONE` | 已完成（客户已评价或管理员结单） |

**树木健康状态 tree.health_status**

| 值 | 含义 |
| --- | --- |
| `HEALTHY` | 健康 |
| `SUB_HEALTHY` | 亚健康 |
| `SICK` | 病虫害 |
| `DEAD` | 枯死 |

**图片类型 trim_record_image.image_type**

| 值 | 含义 |
| --- | --- |
| `SCENE` | 现场照片（用于 AI 识别） |
| `BEFORE` | 修剪前 |
| `AFTER` | 修剪后 |
| `AI_MARKED` | AI 标注后合成图 |

## 二、认证模块 `/auth`

### 2.1 登录

`POST /auth/login`

请求体：

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 账号 |
| `password` | string | 是 | 密码 |

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "userId": 2,
  "username": "worker01",
  "realName": "张师傅",
  "role": "WORKER",
  "phone": "13800000001",
  "avatar": null,
  "deptId": 3,
  "deptName": "城东养护一队",
  "clientId": null,
  "clientName": null
}
```

### 2.2 获取当前登录用户

`GET /auth/info` → 返回结构同 `2.1` 的 `data`（不含 token）。

### 2.3 退出登录

`POST /auth/logout` → `data: null`（后端无状态，前端清除本地 token 即可）。

### 2.4 修改密码

`POST /auth/password`

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `oldPassword` | string | 是 | 原密码 |
| `newPassword` | string | 是 | 新密码（6~20 位） |

## 三、组织架构模块 `/depts`（管理员）

### 3.1 部门/养护队树

`GET /depts/tree` → `data` 为树形数组：

```json
[
  { "id": 1, "parentId": 0, "deptName": "智慧园林集团", "deptType": "DEPT",
    "leader": "李总", "phone": "13900000000", "children": [
      { "id": 2, "parentId": 1, "deptName": "城东养护中心", "deptType": "DEPT", "children": [
        { "id": 3, "parentId": 2, "deptName": "城东养护一队", "deptType": "FLEET", "children": [] }
      ]}
    ]}
]
```

### 3.2 部门列表（平铺）

`GET /depts/list?deptName=&deptType=` → `data` 为平铺数组。

### 3.3 新增部门

`POST /depts` — 请求体：`parentId, deptName, deptType, leader, phone, sort`

`DELETE /depts/{id}` — 若存在子节点或已关联用户，返回 `code=500` 并提示原因。

## 七、文件上传模块 `/files`

### 7.1 上传图片

`POST /files/upload`　`Content-Type: multipart/form-data`

| 参数 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | jpg / jpeg / png / webp，单文件 ≤ 10MB |
| `bizType` | string | 否 | `tree` / `trim` / `ai`，用于子目录归类 |

## 八、AI 识别模块 `/ai`

### 8.1 提交识别

`POST /ai/analyze`

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `imageUrl` | string | 是 | 现场照片地址（`/files/upload` 返回） |
| `treeId` | number | 否 | 树木 ID，用于取树种等先验信息 |
| `taskId` | number | 否 | 任务 ID，用于结果关联 |
| `species` | string | 否 | 树种，缺省时由 `treeId` 反查 |
| `remark` | string | 否 | 养护人员补充说明 |

响应 `data`（`AiAnalyzeVO`）：

```json
{
  "analysisId": 12,
  "taskId": 8,
  "treeId": 1,
  "imageUrl": "/upload/trim/202610/a.jpg",
  "markedImageUrl": null,
  "confidence": 0.87,
  "isMock": true,
  "modelVersion": "mock-v1.0",
  "suggestion": "该香樟树冠内膛枝过密，建议：1) 剪除树冠下部 3 根下垂枝，避免遮挡路灯与行人通行；2) 疏除交叉重叠的内膛枝，改善通风透光；3) 保留主枝延长枝与结果母枝，剪口距枝条基部 1-2cm，呈 45° 斜面，并涂抹愈合剂。整体造型建议维持自然开心形。",
  "cutBranches": [
    { "x1": 0.32, "y1": 0.55, "x2": 0.18, "y2": 0.78, "label": "下垂枝" },
    { "x1": 0.61, "y1": 0.48, "x2": 0.74, "y2": 0.72, "label": "交叉枝" }
  ],
  "keepBranches": [
    { "x1": 0.50, "y1": 0.90, "x2": 0.45, "y2": 0.45, "label": "主干" },
    { "x1": 0.50, "y1": 0.62, "x2": 0.72, "y2": 0.35, "label": "主枝延长枝" }
  ],
  "createTime": "2026-10-18 15:30:12"
}
```

**坐标说明**：`x1,y1,x2,y2` 均为 **归一化坐标（0~1，相对于原图宽高）**，前端以 `left = x * width`、`top = y * height` 换算到 SVG 画布，因此任意分辨率图片都能正确覆盖标注。`lineColor` 由前端决定：`cutBranches` 画红线（建议剪除），`keepBranches` 画绿线（建议保留）。

### 8.2 查询分析结果

`GET /ai/result?taskId=8` → `AiAnalyzeVO`（该任务最近一次分析结果，无则 `data: null`）。

### 8.3 获取 AI 建议文本

`GET /ai/suggestion?taskId=8` → `{ "suggestion": "..." }`

## 九、修剪需求模块 `/trim-requests`

### 9.1 客户发起需求

`POST /trim-requests`

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `treeId` | number | 是 | 需修剪的树木 ID（须属于当前客户） |
| `appointTime` | string | 是 | 预约时间，`yyyy-MM-dd HH:mm:ss` |
| `location` | string | 是 | 地点（默认取树木位置） |
| `trimType` | string | 否 | 期望修剪类型 |
| `remark` | string | 否 | 备注 |

响应 `data`：`{ "requestId": 7, "requestNo": "TR202610180001" }`

### 9.2 需求分页查询（管理员）

`GET /trim-requests/page?pageNum=&pageSize=&status=&clientId=&keyword=`

`data.list` 元素（`TrimRequestVO`）：`id, requestNo, treeId, treeCode, species, clientId, clientName, appointTime, location, trimType, remark, status, auditRemark, createTime`

### 9.3 我的需求（客户）

`GET /trim-requests/my?status=` → `TrimRequestVO` 数组

### 9.4 审核派单（管理员）

`PUT /trim-requests/{id}/audit`

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 是 | `AUDITED`（通过并派单）/ `REJECTED`（驳回） |
| `workerId` | number | 否 | 派单给哪个养护人员；`status=AUDITED` 时必填 |
| `planTime` | string | 否 | 计划修剪时间，缺省取客户预约时间 |
| `auditRemark` | string | 否 | 审核意见 |

响应 `data`：`{ "taskId": 9, "taskNo": "TK202610180001" }`（`REJECTED` 时 `data: null`）

### 9.5 取消需求（客户）

`PUT /trim-requests/{id}/cancel`

### 9.6 删除需求（管理员）

`DELETE /trim-requests/{id}`

## 十、修剪任务模块 `/trim-tasks`

### 10.1 任务分页查询

`GET /trim-tasks/page?pageNum=&pageSize=&status=&workerId=&clientId=&keyword=`

`data.list` 元素（`TrimTaskVO`）：`id, taskNo, requestId, treeId, treeCode, species, area, location, workerId, workerName, clientId, clientName, trimType, planTime, finishTime, status, priority, description, createTime`

### 10.2 我的任务（养护人员）

`GET /trim-tasks/my?status=` → `TrimTaskVO` 数组

### 10.3 任务详情

`GET /trim-tasks/{id}` → `TrimTaskVO`（另含 `record` 字段，若已提交记录则返回 `TrimRecordVO`）

### 10.4 接单

`PUT /trim-tasks/{id}/accept` → 状态 `PENDING → ACCEPTED`

### 10.5 开始修剪

`PUT /trim-tasks/{id}/start` → 状态 `ACCEPTED → PROCESSING`

### 10.6 提交修剪记录

`PUT /trim-tasks/{id}/submit`

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `trimType` | string | 是 | 实际修剪类型 |
| `actualTrimTime` | string | 是 | 实际修剪时间 |
| `cutBranchCount` | number | 否 | 剪除枝条数 |
| `keepBranchCount` | number | 否 | 保留枝条数 |
| `workContent` | string | 是 | 实际修剪情况说明 |
| `aiSuggestion` | string | 否 | 采纳的 AI 建议文本 |
| `images` | array | 否 | 图片列表 `[{ url, imageType }]`，`imageType` 取 `BEFORE`/`AFTER`/`SCENE`/`AI_MARKED` |

响应 `data`：`{ "recordId": 15 }`，任务状态置为 `SUBMITTED`。

### 10.7 改派任务（管理员）

`PUT /trim-tasks/{id}/assign?workerId=3`

### 10.8 结单（管理员）

`PUT /trim-tasks/{id}/finish` → 状态 `SUBMITTED → DONE`
