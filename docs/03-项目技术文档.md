## 一、项目概述

### 1.1 项目定位

本平台把园林与果园的树木修剪从「经验驱动」升级为「数据 + AI 驱动」，覆盖如下闭环：

> 任务派发 → 现场拍照 → AI 识别 → 方案可视 → 现场实施 → 记录归档 → 客户评价 → 数据看板

管理端完成账号/组织/树木档案管理与数据统计，作业端完成接单与修剪执行，客户端完成需求发起、报告查看与评分。

### 1.2 三个角色与功能范围

| 角色 | 代码 | 功能范围 |
| --- | --- | --- |
| 管理员 | `ADMIN` | 账号管理、组织架构（部门/养护队）、客户主体、树木档案、修剪需求审核派单、任务管理（改派/结单）、全量修剪记录查看、数据看板统计 |
| 养护人员 | `WORKER` | 我的任务（接单/开始修剪/提交记录）、上传现场照片、调用 AI 识别获取修剪方案、填写实际修剪情况 |
| 客户 | `CLIENT` | 名下树木与生长档案、发起修剪需求（可取消）、修剪报告查看、对记录评分与评语、评分趋势 |

前后端页面与路由一一对应，见「二、系统架构」与前端路由表。

## 二、系统架构

### 2.1 生产态请求链路（文字版架构图）

```
                    ┌──────────────────────────────────────────┐
   浏览器  ───────► │  Nginx (:80)  deploy/nginx/nginx.conf       │
                    │  ├─ location /         → 前端静态资源 dist  │
                    │  │     （history 模式 try_files /index.html）│
                    │  ├─ location /api/     → 反向代理后端       │
                    │  └─ location /upload/  → 静态托管上传目录    │
                    └───────────────────┬───────────────────────┘
                                        │ proxy_pass http://127.0.0.1:8080
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │  Spring Boot 内置 Tomcat                    │
                    │  server.port = 8080  context-path = /api    │
                    │  Controller → Service → Mapper              │
                    └───────────────────┬───────────────────────┘
                                        │ MyBatis（XML SQL）+ HikariCP
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │  SQL Server :1433  database = smart_garden  │
                    └──────────────────────────────────────────┘
                                        ▲
                                        │ HTTP（provider=http 时可选）
                    ┌───────────────────┴───────────────────────┐
                    │  真实 AI 模型服务（预留，见第七章）          │
                    └──────────────────────────────────────────┘
```

- Nginx `location /api/` 的 `proxy_pass` **不带路径**，保留原始 URI（含 `/api` 前缀），与后端 `context-path=/api` 严格对齐。
- Nginx `location /upload/` 用 `alias` 直接托管后端上传目录，需保证与 `garden.file.upload-path`（生产为 `/opt/smart-garden/upload`）指向同一物理路径。
- 生产态前后端**同源**（统一由 Nginx 80 端口入口），无需跨域。

### 2.2 开发态请求链路

```
   浏览器 ──► Vite Dev Server (:5173, frontend/vite.config.js)
              ├─ /api    → proxy → http://localhost:8080
              └─ /upload → proxy → http://localhost:8080
```

前端请求基地址取自环境变量 `VITE_API_BASE=/api`（见 `frontend/.env.development`），因此开发态与生产态的接口路径完全一致，仅代理目标不同。图片基地址 `VITE_FILE_BASE` 开发态为空、生产态为空（同源），均在 `utils/index.js` 的 `joinFileUrl()` 中拼接。

### 2.3 请求在各层的处理顺序

1. 请求进入内置 Tomcat，命中 `context-path=/api`。
2. 跨域过滤器 `config/CorsConfig.java`（`Ordered.HIGHEST_PRECEDENCE`）先处理，放行预检 `OPTIONS`。
3. 登录拦截器 `config/JwtInterceptor.java` 解析 `Authorization: Bearer <token>`，写入 `util/SecurityUtil.java` 的 `ThreadLocal`；请求结束在 `afterCompletion` 清理。
4. 命中 `controller/*`，参数经 jakarta validation 校验，转 `service/*` 业务层。
5. Service 层做**角色权限校验**与业务规则校验，调用 `mapper/*`。
6. `Mapper` 通过 `resources/mapper/*.xml` 执行 SQL，返回 `entity/VO`。
7. Controller 统一包装为 `common/Result`（分页为 `PageResult`）返回；异常由 `common/exception/GlobalExceptionHandler` 兜底。

#### 分层职责与依赖方向（按规范分包）

| 包 | 职责 | 依赖方向 |
| --- | --- | --- |
| `controller` | 接收 HTTP 请求、参数校验、调用 Service、包装 `Result` | 只依赖 `service`、`dto`、`vo`、`common` |
| `service` / `service.impl` | 业务规则、角色权限校验、事务、多表编排 | 依赖 `mapper`、`entity`、`dto`、`vo`、`util`、`common` |
| `mapper` | 声明数据库操作方法（SQL 位于 XML） | 只依赖 `entity`、`vo`、`@Param` |
| `entity` | 与数据库表字段一一对应 | 无业务依赖 |
| `dto` | Controller 入参（带校验注解） | 无 |
| `vo` | 出参，可聚合多表字段 | 无 |
| `common` / `config` / `util` | 全局能力（响应体、异常、鉴权、上传、序列化） | 被上层引用，自身不反向依赖业务 |

**依赖方向恒为自上而下**：`controller → service → mapper → 数据库`，禁止反向调用，禁止 Controller 直连 Mapper。

## 四、后端设计说明

### 4.1 统一响应体 `common/Result.java`

所有接口返回 `{code, msg, data}`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | 见 `common/ResultCode.java` |
| `msg` | String | 提示信息 |
| `data` | T | 业务数据 |

`ResultCode` 枚举：`SUCCESS(200)`、`UNAUTHORIZED(401)`、`FORBIDDEN(403)`、`BAD_REQUEST(400)`、`ERROR(500)`。静态工厂方法：`ok()` / `ok(data)` / `ok(msg,data)` / `fail(msg)` / `fail(code,msg)` / `fail(resultCode)`。

### 4.2 分页 `common/PageResult.java` 与 `common/PageQuery.java`

- `PageResult<T>` 仅含 `total`、`list`，由 `PageResult.of(total, list)` 构造，`empty()` 返回空结果。
- `PageQuery` 是分页 DTO 基类，字段 `pageNum`（默认 1，`<1` 归 1）、`pageSize`（默认 10，上限 500）；关键方法 `getOffset()` 返回 `(pageNum-1)*pageSize`，供 XML 中 SQL Server 分页使用。
- 分页查询分两步：`countXxxPage(query)` 取总数 + `selectXxxPage(query)` 取当前页，XML 中统一写作：

```sql
ORDER BY tk.create_time DESC, tk.id DESC
OFFSET #{offset} ROWS FETCH NEXT #{pageSize} ROWS ONLY
```

### 4.3 全局异常 `common/exception/`

- `BusinessException`：Service 层校验不通过时抛出，携带 `code`（默认 500，可指定 401/403）。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）统一兜底并转 `Result`：
  - `BusinessException` → `Result.fail(e.code, e.msg)`
  - `MethodArgumentNotValidException` / `BindException` → 400，拼接字段错误信息
  - `MissingServletRequestParameterException` → 400「缺少请求参数」
  - `HttpRequestMethodNotSupportedException` → 400「不支持的请求方法」
  - `Exception` → 500「系统异常」

这样前端**永远不会因 5xx 拿不到 `msg`**。

### 4.4 JWT 无状态鉴权

| 组件 | 文件 | 职责 |
| --- | --- | --- |
| 令牌生成/解析 | `util/JwtUtil.java` | HS256 签发，`subject=userId`，claims 含 `username/realName/role/deptId/clientId`；`resolveToken()` 去除 `Bearer ` 前缀 |
| 登录拦截 | `config/JwtInterceptor.java` | 除放行路径外，所有请求校验令牌，解析后 `SecurityUtil.set(user)`；`OPTIONS` 预检直接放行；请求结束 `SecurityUtil.clear()` |
| 上下文 | `util/SecurityUtil.java` | `ThreadLocal<LoginUser>`，提供 `getRequired()`、`getUserId()`、`getRole()`、`isAdmin()/isWorker()/isClient()`、`currentClientId()` |

配置项（`application.yml` → `garden.jwt`）：`secret`（≥32 字节）、`expire-hours=24`、`header=Authorization`、`prefix="Bearer "`。

放行路径（`config/WebMvcConfig.java`）：`/auth/login`、`/auth/logout`、`/error`、`/upload/**`。

### 4.5 角色权限校验位置

**业务角色校验统一在 Service 层**完成，通过 `SecurityUtil` 判断：

| 判定 | 使用示例 |
| --- | --- |
| `checkAdmin()`（`isAdmin()`） | `TrimRequestServiceImpl.page`、`audit`、`delete`；`TrimTaskServiceImpl.page`、`assign`、`finish`；`TrimRecordServiceImpl.page`；`StatServiceImpl` 全部方法 |
| `isWorker()` | `TrimTaskServiceImpl.myTasks`、`loadOwnTask`（并校验任务归属当前人员）；`AiServiceImpl.analyze` |
| `isClient()` + `currentClientId()` | `TrimRequestServiceImpl.create`（校验树木归属）、`myRequests`、`cancel`；`TrimRecordServiceImpl.myRecords`、`evaluate`、`myTrend` |

不满足角色时抛出 `BusinessException(ResultCode.FORBIDDEN)` → 返回 `403`。

> 说明：`JwtInterceptor` 中另有一条「URI 含 `/admin/` 且非管理员则 403」的规则，但当前所有 Controller 均挂在业务前缀（`/users`、`/depts`、`/trees` 等）下，不使用 `/admin/` 前缀，因此该规则的实质拦截由 **Service 层的 `checkAdmin()`** 承担。

### 4.6 日期序列化 `config/JacksonConfig.java`

通过 `Jackson2ObjectMapperBuilderCustomizer` 统一 Java 8 时间类型的**序列化与反序列化**格式：

| 类型 | 格式 |
| --- | --- |
| `LocalDateTime` | `yyyy-MM-dd HH:mm:ss` |
| `LocalDate` | `yyyy-MM-dd` |
| `LocalTime` | `HH:mm:ss` |

前端拿到的日期字符串无需二次转换（`utils/index.js` 的 `formatDateTime()` 直接原样展示）。`application.yml` 中 `spring.jackson.time-zone=GMT+8`、`write-dates-as-timestamps=false`。

### 4.7 文件上传 `util/FileUtil.java` + 静态映射

- `FileUtil.saveImage(file, bizType)`：按「业务类型 / 年月」分目录，文件名为 `yyyyMMddHHmmss_8位UUID.ext`；示例 `./upload/trim/202610/20261018153012_a1b2c3d4.jpg`，返回相对 URL `/upload/trim/202610/...`。

## 六、核心业务流程

### 6.1 全流程概览（含接口路径与状态流转）

```
① 客户发起需求         POST /trim-requests                     → trim_request.status = PENDING
② 管理员审核
   ├─ 驳回            PUT  /trim-requests/{id}/audit (REJECTED)  → status = REJECTED（data 返回 null）
   └─ 通过并派单      PUT  /trim-requests/{id}/audit (AUDITED)   → 新建 trim_task(status=PENDING,
                                                                   priority=1) + request.status=DISPATCHED
                                                                   data 返回 {taskId, taskNo}
③ 养护人员接单         PUT  /trim-tasks/{id}/accept              → trim_task: PENDING → ACCEPTED
④ 开始修剪             PUT  /trim-tasks/{id}/start               → trim_task: ACCEPTED → PROCESSING
⑤ 上传现场照片         POST /files/upload                        → 返回 {name, url}（bizType=trim）
⑥ 调用 AI 识别         POST /ai/analyze                          → 返回 AiAnalyzeVO（红线剪除 / 绿线保留）
                                                                   + 落库 ai_analysis
⑦ 提交修剪记录         PUT  /trim-tasks/{id}/submit              → 新建 trim_record(status=SUBMITTED)
                                                                   + 批量写 trim_record_image
                                                                   + trim_task: PROCESSING → SUBMITTED（写 finish_time）
⑧ 客户评价             POST /trim-records/{id}/evaluate          → trim_record.status=EVALUATED
                                                                   + trim_task.status=DONE
⑨ 管理员数据看板       GET  /stat/overview 等                     → 指标统计
```

### 6.2 分步时序说明

1. **客户发起需求**（`TrimRequestServiceImpl.create`）
   - 校验登录用户为 `CLIENT`，取 `currentClientId()`；按 `treeId` 载入树木并校验 `tree.clientId == clientId`，否则 403。
   - 生成需求单号 `TR + yyyyMMdd + 4 位流水`；`location` 缺省取树木位置；`status=PENDING`。返回 `{requestId, requestNo}`。

2. **管理员审核派单**（`TrimRequestServiceImpl.audit`，`@Transactional`）
   - 校验 `ADMIN`；需求必须存在且 `status=PENDING`，否则报「当前需求状态不可审核」。
   - `REJECTED`：置 `status=REJECTED`，写 `auditorId/auditRemark/auditTime`，返回 `null`。
   - `AUDITED`：必须传 `workerId`，且该用户角色为 `WORKER`；自动新建 `trim_task`（`taskNo = TK+yyyyMMdd+4位流水`、`status=PENDING`、`priority=1`、`planTime` 缺省取预约时间、`description` 取需求备注），随后把需求置为 `DISPATCHED`，返回 `{taskId, taskNo}`。

3. **接单 → 开始修剪**（`TrimTaskServiceImpl.accept/start`）
   - `loadOwnTask(id)`：校验 `WORKER`、任务存在、`task.workerId == 当前用户`，否则 404/403。
   - `accept`：仅 `PENDING` 可接单 → `ACCEPTED`；`start`：仅 `ACCEPTED` 可开始 → `PROCESSING`。

4. **上传现场照片**：`POST /files/upload`（`bizType=trim`），`FileUtil` 落盘并返回相对 URL（`/upload/trim/yyyyMM/...`）。

5. **AI 识别**（`AiServiceImpl.analyze`，见第七章）：`POST /ai/analyze`，校验 `WORKER`；树种优先取入参 `species`，其次由 `treeId` 反查 `tree.species`；调用识别策略（mock/http），结果落库 `ai_analysis`，返回 `AiAnalyzeVO`。

6. **提交修剪记录**（`TrimTaskServiceImpl.submit`，`@Transactional`）
   - 任务必须为 `PROCESSING`；新建 `trim_record`（`taskId/treeId/workerId/clientId` 取自任务，`status=SUBMITTED`）；批量插入 `trim_record_image`（`imageType` 缺省 `SCENE`）；任务 `updateAfterSubmit` → `status=SUBMITTED` 并写 `finish_time`。返回 `{recordId}`。

7. **客户评价**（`TrimRecordServiceImpl.evaluate`，`@Transactional`）
   - 校验 `CLIENT` 且记录 `clientId == currentClientId()`；写 `score/comment/evaluateTime`、记录 `status=EVALUATED`；若 `taskId` 非空，把任务置 `DONE`。

8. **管理员看板**（`StatServiceImpl`）：`overview/area/trend/species/worker`，其中趋势按天补零、平均分保留两位小数。

9. **其他管理员动作**：改派 `PUT /trim-tasks/{id}/assign?workerId=`（`updateWorker` 会把任务状态重置为 `PENDING`）；结单 `PUT /trim-tasks/{id}/finish`（仅 `SUBMITTED` 可结单 → `DONE`）；需求删除 `DELETE /trim-requests/{id}`。

### 6.3 状态枚举与流转

**需求状态 `trim_request.status`**

| 值 | 含义 | 触发动作 |
| --- | --- | --- |
| `PENDING` | 待审核 | 客户发起需求（`create`） |
| `AUDITED` | 已审核待派单 | 字典保留值（当前审核通过直接进入 `DISPATCHED`） |
| `DISPATCHED` | 已派单 | 管理员审核通过并派单（`audit`） |
| `COMPLETED` | 已完成 | 字典保留值（当前流程未自动回写；`init_data.sql` 演示数据存在该状态） |
| `REJECTED` | 已驳回 | 管理员驳回（`audit`） |
| `CANCELLED` | 已取消 | 客户取消（`cancel`，仅 `PENDING`/`AUDITED` 可取消） |

**任务状态 `trim_task.status`**

| 值 | 含义 | 触发动作 |
| --- | --- | --- |
| `PENDING` | 待接单 | 审核派单生成 / 管理员改派（`assign` 重置） |
| `ACCEPTED` | 已接单 | 养护人员接单（`accept`） |
| `PROCESSING` | 修剪中 | 开始修剪（`start`） |
| `SUBMITTED` | 已提交记录 | 提交记录（`submit`） |
| `DONE` | 已完成 | 客户评价（`evaluate`）或管理员结单（`finish`） |

**记录状态 `trim_record.status`**：`SUBMITTED`（提交时）→ `EVALUATED`（客户评价后）。

> 一致性说明：需求状态与任务状态由**不同表**独立维护，二者不存在数据库级外键与级联，Status 的同步在 Service 层显式完成（如评价同时改记录与任务）。

## 七、AI 枝条识别模块

### 7.1 模块结构（策略模式 + 配置开关）

```
controller  AiController（/ai/analyze、/ai/result、/ai/suggestion）
                │
                ▼
service     AiServiceImpl  ──负责校验、取树种、落库 ai_analysis──┐
                │                                               │
                ▼                                               │
          BranchAnalysisService（策略接口）                       │
                ├── MockBranchAnalysisServiceImpl  provider=mock（默认，matchIfMissing）│
                └── HttpBranchAnalysisServiceImpl  provider=http ← garden.ai.endpoint/api-key/timeout
```

- 接口 `service/BranchAnalysisService.java`：`AiAnalyzeVO analyze(AiAnalyzeDTO dto)`。
- 两个实现均用 `@ConditionalOnProperty(name="garden.ai.provider")` 按配置互斥装配，业务代码无需感知具体实现。

### 7.2 Mock 返回的数据结构、红线/绿线含义

`MockBranchAnalysisServiceImpl` 以 `species + imageUrl` 的哈希作为随机种子，**相同输入恒定产出**（可复现）：

- 剪除枝条（红线）2~4 条，标签取自 `下垂枝 / 交叉枝 / 病虫枝 / 内膛枝 / 徒长枝`。
- 保留枝条（绿线）2~3 条，标签取自 `主干 / 主枝延长枝 / 结果母枝 / 健康侧枝`。
- `confidence` 取 `0.78~0.95`，`isMock=true`，`modelVersion="mock-v1.0"`。
- `suggestion` 为统一模板 + 树种拼接，含「剪除项 / 保留项 / 剪口处理 / 造型建议」四段。

**坐标含义**：线段 `x1,y1,x2,y2` 为**归一化坐标（0~1，相对于原图宽高）**，前端 `BranchMarkCanvas.vue` 用 `viewBox="0 0 1 1"` + `preserveAspectRatio="none"` 的 SVG 覆盖层直接映射，任意分辨率图片都能正确覆盖。`lineColor` 由前端约定：`cutBranches` 画红线（`#f5222d`，建议剪除），`keepBranches` 画绿线（`#52c41a`，建议保留）。

`BranchLineVO`（`vo/BranchLineVO.java`）字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `x1` / `y1` | Double | 起点归一化坐标 |
| `x2` / `y2` | Double | 终点归一化坐标 |
| `label` | String | 枝条标签（如「下垂枝」「主干」） |

`AiAnalyzeVO`（`vo/AiAnalyzeVO.java`）：`analysisId、taskId、treeId、imageUrl、markedImageUrl、confidence、isMock、modelVersion、suggestion、cutBranches、keepBranches、createTime`。

### 7.3 `ai_analysis` 落库字段映射（`AiServiceImpl`）

| 实体字段 | 来源 |
| --- | --- |
| `taskId` / `treeId` / `imageUrl` | 入参 `AiAnalyzeDTO` |
| `species` | 入参，或 `treeId` 反查 `tree.species`，缺省「未知树种」 |
| `markedImageUrl` | AI 结果 |
| `cutBranches` / `keepBranches` | 由 `ObjectMapper` 将 `List<BranchLineVO>` 序列化为 JSON 字符串 |
| `suggestion` / `confidence`（转 `BigDecimal`）/ `modelVersion` | AI 结果 |
| `isMock` | `1`（Mock）/ `0`（真实） |

查询时 `AiAnalysisMapper.selectLatestByTaskId(taskId)` 取该任务最近一次结果，`toVo` 反序列化 JSON 为线条列表。

### 7.4 如何切换到真实模型

**只需修改配置，业务代码零改动**（`AiServiceImpl`、`AiController`、前端均无需变更）：

1. 编辑 `backend/src/main/resources/application.yml`（或生产 `deploy/tomcat/application-prod.yml`）：

```yaml
garden:
  ai:
    provider: http                       # 由 mock 改为 http
    endpoint: http://<真实模型地址>/api/v1/branch/analyze
    api-key: "<模型服务访问密钥>"          # 非空时以 api-key 请求头携带
    timeout: 10000                       # 毫秒，作用于 RestTemplate 连接与读取超时
```

2. 重启后端。`HttpBranchAnalysisServiceImpl` 生效（`@ConditionalOnProperty`），`RestTemplateConfig.aiRestTemplate` 按 `timeout` 配置超时。
3. 真实服务返回的 JSON **只需与 `docs/02-接口文档.md` 第 8.1 节的 `data` 结构一致**（即 `AiAnalyzeVO`：`cutBranches`/`keepBranches` 为 `[{x1,y1,x2,y2,label}]`），即可被 `objectMapper.readValue(response, AiAnalyzeVO.class)` 直接解析。

`HttpBranchAnalysisServiceImpl` 转发行为：`POST endpoint`，`Content-Type: application/json`，请求体含 `imageUrl/treeId/taskId/species/remark`；`api-key` 非空时写入请求头 `api-key`。

### 7.5 对接真实模型时需要注意的约定

| 约定 | 要求 |
| --- | --- |
| 鉴权头 | 当前固定为请求头 `api-key`（非 `Authorization`）。若真实服务用其它头名，需同步调整 `HttpBranchAnalysisServiceImpl`（属接入适配范围，非业务代码） |
| 超时 | 连接与读取超时由 `garden.ai.timeout`（毫秒）统一控制；模型推理较慢时应适当调大，并注意 Nginx `proxy_read_timeout`（默认 60s） |
| 坐标系 | 坐标必须是**归一化 0~1**（相对原图宽高），非像素值；否则红线/绿线无法与图片对齐 |
| 字段命名 | 必须返回 `cutBranches` / `keepBranches` / `suggestion` / `confidence` / `markedImageUrl` / `modelVersion`，且 `BranchLineVO` 使用 `x1/y1/x2/y2/label`；字段名不一致会导致反序列化为空或异常 |
| `isMock` | 真实模型返回应使 `isMock=false`（或省略，落库按 `0` 处理），便于区分数据来源 |
| 返回空值 | `response` 为空会抛「AI 模型服务返回为空」；解析失败会抛「AI 模型服务调用失败」，均以业务异常返回前端 |

## 十、开发规范

### 10.1 后端命名与分包规范

- 包名固定 `com.garden.smarttrim`，按 `controller / service / service.impl / mapper / entity / dto / vo / config / util / common` 分包；**禁止** Controller 直接访问 Mapper。
- 命名：`XxxController`、`XxxService`、`XxxServiceImpl`、`XxxMapper`、`XxxDTO`（入参）、`XxxVO`（出参）、`Xxx`（实体，与表同名驼峰化）。
- 依赖方向自上而下：`controller → service → mapper`，禁止反向依赖与循环依赖。
- 类/字段使用 Lombok `@Data`（`service.impl` 用 `@RequiredArgsConstructor` 构造注入），减少样板代码。

### 10.2 SQL 编写规范

- **所有 SQL 一律写在 `backend/src/main/resources/mapper/*.xml`**，Mapper 接口只声明方法签名（可加 `@Param`）。
- **禁止使用 MyBatis 注解 SQL**（如 `@Select`/`@Insert`），以保证 SQL 可独立 Review、可复制到客户端执行、动态 SQL（`<if>`/`<foreach>`/`<where>`）可读。
- 分页统一 `OFFSET #{offset} ROWS FETCH NEXT #{pageSize} ROWS ONLY`，且**必须带 `ORDER BY`**（如 `ORDER BY create_time DESC, id DESC`）。
- 单号前缀统计使用 `LIKE #{prefix} + '%'`（SQL Server 字符串拼接），日期过滤用 `CAST(... AS DATE)` 与 `DATEADD(DAY,1,...)`。
- 新增用 `useGeneratedKeys="true" keyProperty="id"` 回填主键；时间默认值由 `SYSDATETIME()` 或 SQL 默认值负责。

### 10.3 统一响应与异常规范

- 所有 Controller 返回 `Result<T>`（列表用 `Result<List<T>>`，分页用 `Result<PageResult<T>>`），统一 `Result.ok(...)`。
- 业务校验失败抛 `BusinessException`（可指定 401/403），**不要**在 Controller 里手写 try/catch —— 交由 `GlobalExceptionHandler` 统一处理。
- 状态码语义：200 成功 / 401 未登录 / 403 无权限 / 400 参数错误 / 500 业务或系统异常。

### 10.4 中文注释要求

- 类、公开方法、关键字段、复杂 SQL 均需**中文注释**；实体字段注释对应数据库字段含义。
- 配置项（`application.yml`）与 Mapper XML 需有中文说明，便于 DBA 与运维理解。

### 10.5 前端目录与命名规范

- 目录：`api / components / layout / router / store / utils / views`（`views` 按角色分子目录 `admin / worker / client`）。
- 命名：组件文件 PascalCase（如 `PageTable.vue`），页面统一 `index.vue`（详情页可 `detail.vue`），api 文件按业务模块命名（如 `trimTask.js`）。
- 通用组件复用：`PageTable.vue`（分页表格）、`ImageUpload.vue`（图片上传）、`BranchMarkCanvas.vue`（AI 标注画布）、`StatCard.vue`、`BaseChart.vue`。

### 10.6 请求封装与拦截器约定（`utils/request.js`）

- Axios 实例 `baseURL = import.meta.env.VITE_API_BASE || '/api'`，`timeout=30000`。
- 请求拦截器：有 token 时注入 `Authorization: Bearer <token>`。
- 响应拦截器：统一解包 `{code,msg,data}`，`code===200` 只把 `data` 交给业务代码；`401` 清空登录态并跳登录页；`403` 提示无权限；其余弹 `msg`。
- token 存取见 `utils/auth.js`（localStorage 键 `smart_garden_token`）；用户信息键 `smart_garden_user`。

### 10.7 枚举中文映射（`utils/index.js`）

前端集中维护枚举映射，**严格对齐接口文档 1.5 节**：`ROLE_TEXT`、`REQUEST_STATUS_TEXT`、`TASK_STATUS_TEXT`、`HEALTH_STATUS_TEXT`、`IMAGE_TYPE_TEXT`、`RECORD_STATUS_TEXT`、`DEPT_TYPE_TEXT`、`TRIM_TYPE_OPTIONS`，以及 `roleText()/requestStatusText()/taskStatusText()` 等转换函数与 `joinFileUrl()`（拼接 `VITE_FILE_BASE`）、`nowDateTime()`、`formatDateTime()`。

### 10.8 权限守卫（`router/index.js`）

- 白名单：`/login`、`/403`、`/404`。
- 全局前置守卫：无 token → `/login`；有 token 无用户信息 → `fetchInfo()`；`/` 按 `userStore.homePath`（`ROLE_HOME`：ADMIN→`/admin/dashboard`、WORKER→`/worker/task`、CLIENT→`/client/tree`）跳转。
- `route.meta.roles` 声明可访问角色，不匹配则跳 `/403`；侧边菜单由路由表按角色过滤生成。

## 十一、常见问题与排查（FAQ）

### Q1：接口返回 401（未登录/登录已过期）
**现象**：`{"code":401,"msg":"未登录或登录已过期，请重新登录"}`。
**排查**：
1. 请求是否带 `Authorization: Bearer <token>`（`utils/request.js` 请求拦截器会自动注入，检查 localStorage 中 `smart_garden_token` 是否存在）。
2. 令牌是否过期：`garden.jwt.expire-hours=24`（小时），过期需重新登录。
3. 密钥是否一致：`garden.jwt.secret` 属 HS256，长度须 ≥32 字节；更换密钥会使旧 token 全部失效。
4. 是否命中放行路径（`/auth/login`、`/auth/logout`、`/error`、`/upload/**`）。

### Q2：接口返回 403（已登录但无权限）
**现象**：`{"code":403,"msg":"无权限访问该资源"}`。
**排查**：该错误由 **Service 层**角色校验抛出（`SecurityUtil.isAdmin()/isWorker()/isClient()`）。核对当前账号角色与接口要求的角色（见第九章）；例如客户调用 `/trim-tasks/page`（ADMIN）会 403，非任务归属人调用 `/trim-tasks/{id}/accept` 也会 403。

### Q3：跨域（CORS）报错
**开发态**：前端 5173 通过 `vite.config.js` 的 proxy 代理 `/api`、`/upload` 到 8080，浏览器视为同源，正常不应出现跨域。
**生产态**：前后端经 Nginx 同源，无需跨域。
**若仍报跨域**：确认 `config/CorsConfig.java` 的 `CorsFilter` 生效（最高优先级，先于 JWT 拦截器）；`allowCredentials=true` 时来源必须用 `allowedOriginPatterns`（已如此配置）。

### Q4：上传的图片 404
**排查**：
1. 后端 `garden.file.upload-path` 与 Nginx `location /upload/` 的 `alias` 必须指向**同一物理目录**（开发态 `./upload`，生产 `deploy/tomcat/application-prod.yml` 为 `/opt/smart-garden/upload`，Nginx `alias /opt/smart-garden/upload/`）。
2. Nginx 进程需对该目录有读权限。
3. 若 Nginx 与后端不同机，改用 `nginx.conf` 中「方式二」把 `/upload/` 反向代理给后端。
4. 确认 `WebMvcConfig` 已把 `/upload/**` 映射为静态资源（开发态直接访问后端也可命中）。

### Q5：SQL Server 连接失败
**排查**：
1. 连接串参数：`encrypt=false` 与 `trustServerCertificate=true`（自签证书场景必须），`loginTimeout=30`。
2. 1433 端口是否放行；SQL Server 配置管理器中**「TCP/IP 协议」是否启用**、IP 地址是否监听 1433。
3. 账号密码：`application.yml` 默认 `sa / Garden@123456`，生产按实际修改。
4. 驱动版本 `mssql-jdbc:12.6.1.jre11` 与 JDK 17 匹配，无需改动。
5. 应用启动日志出现「初始密码加密跳过（数据库未就绪…）」说明连接或表结构尚不满足（`PasswordInitRunner` 仅告警不阻断）。

### Q6：分页查询报错（OFFSET/FETCH 语法错误）
**排查**：SQL Server 的 `OFFSET ... FETCH NEXT` **必须与 `ORDER BY` 一起使用**。本项目所有分页 XML 均已带 `ORDER BY`；若新增分页 SQL 遗漏 `ORDER BY`，会报语法错误。分页参数 `offset` 由 `PageQuery.getOffset()` 计算（`pageNum<1` 归 1，`pageSize` 上限 500）。

### Q7：AI 识别返回 null 或解析失败
**排查**：
1. `GET /ai/result?taskId=` 在无分析记录时设计上返回 `data: null`，属正常。
2. `provider=http` 时，真实模型返回体必须与接口文档 8.1 的 `data` 结构一致；否则 `HttpBranchAnalysisServiceImpl` 解析失败会抛「AI 模型服务调用失败」。
3. 检查 `garden.ai.endpoint` 可达、`api-key` 正确、`timeout` 足够（模型推理慢需调大）。
4. 后端日志（`logging.level.com.garden.smarttrim=debug`）会打印 endpoint 与异常栈。

### Q8：Maven / JDK 版本问题
**排查**：需 JDK 17（`pom.xml` `<java.version>17</java.version>`、maven-compiler-plugin `source/target=17`）。用 `java -version` 与 `mvn -v` 确认；JDK 8/11 无法编译 Spring Boot 3.x。打包产物名为 `smart-garden-trim.jar`（`build.finalName`）。

### Q9：前端刷新页面 404（Nginx）
**现象**：访问深链接（如 `/admin/dashboard`）刷新后 404。
**原因**：Vue Router 使用 history 模式，服务端需把所有路径回退到 `index.html`。
**排查**：确认 Nginx `location /` 配置为 `try_files $uri $uri/ /index.html;`（见 `deploy/nginx/nginx.conf`）。

### Q10：`/api` 请求经 Nginx 返回 404/502
**排查**：
1. `location /api/` 的 `proxy_pass` **不能带路径**（`proxy_pass http://smart_garden_backend;`），否则会丢失 `/api` 前缀；后端 `context-path=/api` 也要求保留前缀。
2. 502 多因后端未启动或 `upstream` 端口不符（后端默认 8080）。
3. 登录接口返回 200 但业务接口 404，核对路径拼写与 Controller `@RequestMapping`。
